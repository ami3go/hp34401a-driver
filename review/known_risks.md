# Known risks — 26.07 baseline / Unreleased remediation

| Risk | Impact | Mitigation/status |
|---|---|---|
| An authoritative `BaseInstrumentLibrary` implementation (RFDS-003's session/state/lifecycle base class) does not exist anywhere -- not as `rfds-core` (never published), and not as `scpi-driver-core` (a real, now-adopted dependency, but one that deliberately governs the RFDS-004 transport layer, not the RFDS-003 BaseInstrumentLibrary layer). | RFDS-003 R-003-1031 cannot be honestly closed; a local imitation could create a divergent shared-core contract. | **OPEN / release blocker (HP34401A-DEV-004).** `scpi-driver-core` is mandatory and version-pinned (see `docs/scpi_driver_core_review.md`), but it does not and will not close this item -- a separate RFDS-003-conformant package would be needed. No local shim/fork. |
| The driver's own transport facade (`hp34401a_dmm/transports.py::Transport`, used by `legacy_driver.py`) is still string-typed at the protocol-layer boundary, not literally bytes per RFDS-004 SS5's architecture diagram, even though it is now backed by `scpi-driver-core`'s byte-oriented transports internally. | Full RFDS-004 v2 architecture conformance at the driver's own boundary is not proven, though the underlying wire-level transport, state model, and simulator now come from an RFDS-004-shaped implementation. | **OPEN deviation HP34401A-DEV-002 (narrowed, not closed).** See `docs/scpi_driver_core_review.md` for exactly what migrated and what didn't. |
| Real HP34401A HIL has not yet been rerun from the final remediated commit. | Physical cable/backend/firmware/terminal behavior remains unqualified. | **OPEN HP34401A-DEV-003 (partial progress).** A real 34401A was identified and answered `*IDN?` correctly during the scpi-driver-core migration; the full HIL suite run is still pending an environment with USB driver-rebind capability (see `guide/real_hardware_host_setup.md`). D0 only; D2/P1 prohibited until exact-commit real HIL evidence exists. |
| Vendor VISA backends differ in clear, timeout, lock, USBTMC, GPIB and termination behavior. | A simulator/core unit pass may not represent a production VISA installation. | Execute the VISA HIL profile for each approved backend/site configuration. |
| RS-232 cabling, DTR/DSR, baud, parity, data bits, stop bits and front-panel configuration are installation-specific. | Connection/remote/local behavior can fail despite software tests. | Use explicit serial configuration and serial HIL. Never infer serial framing. |
| Current measurement can open the DMM fuse or disturb a DUT. | Equipment damage, test interruption, invalid evidence. | Current HIL profiles remain disabled by default and require an approved fused/bounded fixture. |
| Resistance/diode/continuity on an energized DUT are unsafe or invalid. | Equipment damage or false result. | Fixture profile requires verified de-energized DUT; disabled by default. |
| Reset and self-test disturb active instrument state. | Test interruption or loss of configuration. | Explicit risk-tagged calls and separate HIL authorization/profile. |
| Raw SCPI can bypass high-level semantic state tracking. | Unknown instrument state and protocol side effects. | **MITIGATED in remediation.** Robot raw I/O is disabled by package default and requires explicit authorization; calibration remains separately guarded. The active GUI wrapper now requires a fresh operator confirmation for every raw Query/Write service action. |
| Per-session evidence is diagnostic evidence, not physical qualification. | Simulation or ad-hoc evidence could be overstated. | Run-level mode is now UNKNOWN/SIMULATION/REAL_HARDWARE from actual transport. Release/HIL logic still treats simulator evidence as non-physical. |
| RFDS evidence files can contain instrument identity, commands, resources and readings even after credential-key redaction. | Information disclosure if diagnostic bundles are shared without review. | Apply site retention/classification policy before export/archive. |
| Generated API/conformance artifacts can drift if generator code does not understand inherited facade methods. | A future regeneration could overwrite current 109-keyword reviewed artifacts with an incomplete subset. | **MITIGATED in remediation.** Both active generators inspect the effective inherited Robot surface; API generation preserves reviewed semantic/governance metadata; RFDS-019 generation preserves reviewed vector logic; CI/unit tests check the 109-keyword generator surface. |
| Root and packaged RFDS-014 schema/default/lock copies are duplicated for source and wheel access. | Manual edit of only one copy causes source/install divergence. | Byte-parity tests and schema-lock integrity tests fail CI; change both authorities atomically. |
| `site/` is generated rather than committed. | Pages content depends on build tooling. | Repository-root Pages workflow builds strict MkDocs output from reviewed `docs/`/`mkdocs.yml`; source docs are the authority. |
| GitHub Actions currently use major-version action tags. | Supply-chain immutability is below a hardened P1 standard. | Pin reviewed actions to immutable commit SHAs before production/P1 promotion if required by release policy. |
| `release/` candidate integrity files are intentionally pending until the source is frozen. | They must not be mistaken for a signed/current production release. | Release manifest says remediation/pending; build script regenerates provenance/checksums from the exact frozen commit. |
| RFDS-018 bench template contains UNKNOWN facts by design. | Unsafe autonomous multi-driver planning if template is treated as deployed truth. | Keep authoritative deployed system contract in the bench repository and resolve every topology/safety/limit field there. |
